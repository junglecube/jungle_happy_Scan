# V3.12.0 配置与升级说明

V3.12 将两个文件读取规则桶合并为一个公开的 `file_read` 插件，并补充 Linux 常见编码、路径归一化和 file URI 变体。Normal 只执行未标记为 deep 的基础 payload；Deep 执行完整规则。旧客户端仍可提交 `file_read_encoded`，服务端会把它当作一次统一的深度文件读取扫描，不再在插件列表中展示第二张卡片。

文件读取候选参数、文件上传 multipart 字段和短信手机号字段使用受控模糊匹配。匹配会先执行原有大小写不敏感的精确/后缀判断，然后识别数字索引、分隔符和有限的业务修饰词，例如 `filename1`、`file_name[0]`、`pathValue`、`phonekey`。它不会把任意 substring 都当作命中，短信接口仍必须先满足 URL 关键字门控。

配置版本从 34 升到 35。启动时如果发现 `file_read_encoded`，会把它的参数名、路径、模式、payload 和正则合并进 `file_read`，原编码规则标记为 deep，并在写回前创建 `.pre-v35.bak` 备份。现有 `file_read` 自定义规则、其他插件规则、业务响应语义和 Normal 插件列表均保留。只替换可执行文件并重启即可完成迁移，不需要手工修改原 config。

持久配置页面的插件规则卡片改为桌面端两列布局，每张卡片同时显示中文名和英文名；点击后在原卡片位置展开详情，再次点击同一张卡片即可收起。窄屏仍自动切换为单列。

## 建议升级步骤

1. 停止旧版本进程并备份二进制。
2. 用对应平台的 V3.12.0 可执行文件替换原文件，保留 `config/`、证书、签名脚本和 `var/`。
3. 按原启动命令启动。首次打开旧配置时观察日志中的配置迁移结果；迁移失败会保留旧文件并返回错误。
4. 复核【持久配置 → 插件配置区】中的 `file_read` payload 和短信参数名，保存后新任务立即使用新规则。
