# jungle_happy_Scan V3.5 验证矩阵

本报告记录 V3.5 最终验收。V3.3前端性能能力和V3.4 SSRF 回连能力继续作为回归基线；V3.5重点验证 CodeMirror 长行编辑、短信 URL 关键字门控，以及使用 mTLS 客户端证书的 HTTPS 代理明文捕获。

## V3.5 新增验证

1. CodeMirror 6 离线 bundle 已嵌入程序；扫描引擎、拦截器和主要 HTTP 详情视图不再使用透明 textarea 与高亮 pre 叠层。4,000 字符 Cookie/JWT 单行可自动折行、选区和光标位置一致。
2. `sms_abuse` 对 `POST /account/update` 中的 `phone` 不发送任何探测请求；`/sms/send` 保持 60 个并发批次请求；持久规则新增 `message` 后 `/otp/message` 可执行。
3. 浏览器信任 HappyScan CA 后，作用域内 HTTPS 请求可作为明文资产捕获；测试站点要求客户端证书时，上游 TLS 收到该证书，捕获资产和后续自动扫描均使用 `https`。
4. HappyScan CA 证书与私钥均以 `0600` 权限保存；PFX/P12 密码不出现在任务摘要或恢复配置。

## V3.4 SSRF最小验证

1. JSON参数`cmcDomain`由默认`domain`后缀规则识别，执行计划为1个插入点、1个请求。
2. `POST /api/v1/callback/<token>/openapi/v1/envs/apps/1`能够命中已注册Token。
3. `/callback?token=<token>`能够命中，未知或过期Token继续返回404。
4. 回连响应包含不出现在注入URL中的专属标记；业务响应回显该标记时生成严重、已确认SSRF。
5. 仅回显完整Callback URL或Token而未取回专属标记时不生成Finding。

## V3.3 增量性能验收

1. 开启请求或响应拦截后，浏览器只保持一个`wait=1`长轮询；无事件时不出现200毫秒请求，待处理报文到达后通知通道立即唤醒。
2. 拦截摘要只返回`pending`项且不包含Raw；Raw只在当前项变化时读取一次，编辑器聚焦或内容未变化时不重写`value`。
3. 资产、进度、漏洞、拦截Revision独立变化；全局变化使用最长25秒事件通知，扫描进度变化不重新高亮已打开的大请求、响应和证据。
4. 无筛选的历史资产第一页直接遍历最新10个索引节点，不再扫描并排序全部历史资产；漏洞汇总先返回类型计数，点击类型后才加载受影响接口。
5. 代理设置页只读取任务摘要；资产页才读取10条资产和漏洞分组；扫描插件、持久配置与使用手册仅在进入对应页面时加载。
4. 目标URL、监听地址和模式在桌面端同排；目标Host自动进入作用域，附加Host收纳到高级设置。
5. `.css/.js/.png`等默认后缀始终过滤；管理员新增`avif/wasm`后同样过滤；`.jsp`不会因默认规则被过滤。
6. 使用4000字符URL、Header和Body验证扫描引擎编辑层与高亮层：两层`scrollWidth == clientWidth`，均为自动折行且无横向滚动；浏览器控制台无错误或警告。
7. 选择资产后，详情`tr`紧邻选中`tr`且详情组件位于该行内部；重复接口摘要不存在，漏洞Evidence的`details.open`默认均为`false`。
8. 请求、响应、Header与Body计算后的背景色统一为`rgb(255, 250, 240)`；四个概览卡片的标签和值垂直中心一致并位于同一行。

## 1. 本次验收结果

- `go test ./... -count=1`：全部通过，覆盖插件、引擎、传输、配置、API 和 WEB 扫描。
- `go test -race ./internal/webscan ./internal/api ./internal/engine ./internal/transport -count=1`：全部通过，无数据竞争。
- `go vet ./...`：通过。
- JavaScript 语法：`app.js`、`webscan.js` 通过 Node.js `--check`。
- Shell 语法：构建、安装、启动、停止与状态脚本通过 `sh -n`。
- 浏览器实测：创建全局 Passive 代理、捕获 133 次本地请求并形成 79 个去重接口；50 条分页、第二页切换、接口详情按需加载和“复制报文”均正确。
- 范围外流量：环回代理直接转发且不建立资产；非环回代理仍拒绝范围外请求，避免形成远程开放代理。
- 恢复：进程关闭后任务和完整代表报文从压缩文件恢复；代理不自动重启，原排队/运行扫描标记为中断，不重放业务请求。
- 轻量列表：125 个模拟接口分页、搜索、状态筛选通过；列表不包含 Raw 报文和 Finding，站点 Finding 摘要不包含 Evidence。
- 原子落盘：主文件不存在时可读取 Windows 替换流程留下的 `.bak` 恢复副本。

未进行面向生产规模的 1000 长连接或 1 万接口持续压力测试，不把容量建议描述为已完成结果。

## 2. V3.2 功能矩阵

| 能力 | 正向验证 | 负向与边界 |
|---|---|---|
| 生命周期 | 刷新、关闭或后台冻结页面不停止代理、不删除数据；关闭代理保留扫描与历史 | 明确删除任务才清除内存和本地恢复目录 |
| 范围分离 | 环回监听时，目标范围外 HTTP/CONNECT 可正常浏览 | 范围外流量不缓存、不拦截、不建立资产、不扫描；非环回监听继续拒绝 |
| 本地恢复 | `session.json` 与单接口 `.json.gz` 原子保存，重启后可读取完整详情 | 中断中的主动扫描不得自动重放；损坏快照跳过并写日志 |
| 内存降冷 | 热摘要常驻内存，完整 Raw、Baseline、Evidence 落盘后释放 | 手工重扫前必须重新加载基线；关闭时不得用空冷对象覆盖磁盘 |
| 列表 API | 服务端分页、搜索、状态筛选，页大小最高 100 | 列表不得返回 Raw、Baseline 或 Finding 大对象 |
| Finding API | 仅在数量变化时获取不含 Evidence 的摘要 | 只有选择具体接口时才读取完整证据 |
| 前端刷新 | 最长25秒事件通知；变化立即唤醒，后台页停止连接 | 空闲时不轮询，繁忙时不丢失合并刷新事件 |
| 接口详情 | 单接口按需加载代表请求/响应，可复制原始请求 | 关闭详情不会删除资产；重复点击可正常展开/收起 |
| 站点报告 | 按漏洞类型和接口汇总，单接口只渲染一份代表请求/响应 | 同一接口多个 Finding 不重复渲染大块报文 |
| 兼容 | V1/V2 API、V2.4 插件、V3.1 拦截状态机继续通过 | HTTPS 未解密时不得生成虚假的明文接口资产 |
| 命令注入上下文 | JSON `backuppath` 注入反引号curl唯一回连 | 仅收到匹配Token时确认；同时校验管道、逻辑运算、换行、反引号、`$()`默认规则与时间对照完整 |

## 3. 自动化回归重点

```sh
go test ./... -count=1
go test -race ./internal/webscan ./internal/api ./internal/engine ./internal/transport -count=1
go vet ./...
```

测试覆盖：

1. 精确作用域、全局 Passive、环回旁路和远程监听严格边界。
2. HTTP GET/JSON/Form/XML/Multipart 转发、Raw 捕获、动态路径与结构化参数去重。
3. HTTPS CONNECT 透明隧道可用但资产数保持为零。
4. 请求与响应的拦截、修改、Forward、Drop、超时和关闭开关释放。
5. 捕获响应复用首基线，避免原始非幂等 POST 被额外预检。
6. 任务停止保留扫描和记录，显式删除才取消并清理。
7. 异步落盘、冷数据按需读取、恢复后手工重扫。
8. API 分页、查询、状态过滤、摘要裁剪和 `revision`。
9. 全部 V2.4 SQLi 与其他插件正反矩阵。

## 4. 浏览器现场验收

1. 打开【WEB扫描】，空目标默认使用 Passive，代理地址默认 `127.0.0.1:8088`。
2. 启动代理后，浏览测试系统和其他普通网站；只有目标范围内流量进入接口资产。
3. 连续产生 11 条以上不同接口，确认列表默认每页 10 条且切页不重新渲染全部站点证据。
4. 从顶部主导航进入【接口资产】，选择接口后确认请求、响应在表格下方独立详情区按需显示，表格行位置不变化；点击“复制报文”，剪贴板内容与 Raw 请求一致。
5. 展开站点漏洞类型和受影响接口，确认每个接口只显示一份代表请求与响应。
6. 刷新或关闭管理页面后重新打开，确认任务仍在；代理只有管理员点击关闭或进程退出才停止。
7. 重启 HappyScan，确认任务以“已停止”恢复，历史接口可查看，未完成主动扫描显示中断原因。

## 5. 性能与容量建议

当前实现已经避免前端最主要的放大路径：

- 任务摘要不再携带全部 Finding；
- 接口列表固定分页且不返回 Raw；
- `revision` 未变化时不刷新资产与漏洞；
- 无筛选第一页通过按时间维护的增量索引读取，接近 O(10)，不再每次 O(N log N)；
- 漏洞汇总先取分组，只有点击漏洞类型才读取受影响接口；
- 代理设置、资产、扫描引擎、配置和手册按页面懒加载；
- 详情和 Evidence 只在点击后读取；
- 已安全落盘的完整报文从内存降冷；
- 重复接口只覆盖一个压缩快照，不累积多份 Body。

部署前仍建议在目标 Linux 服务器记录：

- 100、500、1000 Keep-Alive 并发下代理 P50/P95 延迟；
- 1 万重复请求去重后的内存与磁盘增量；
- 2000 个不同接口达到任务上限时的行为；
- 自动扫描期间代理转发延迟与扫描队列隔离情况；
- 100 个 CONNECT 隧道的连接、取消和 goroutine 回收。
