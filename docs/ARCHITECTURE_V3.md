# jungle_happy_Scan V3.5 WEB 扫描架构设计

V3.5在V3.4的回连确认和V3.3的增量前端架构上，使用离线打包的 CodeMirror 6 统一处理 HTTP 编辑与查看，消除透明 textarea 与高亮层在长 Cookie、JWT 或折行场景中各自排版而产生的光标错位。WEB 代理新增作用域内 HTTPS 中间人解密：HappyScan 保存权限为 0600 的本地 CA，浏览器信任该 CA 后可捕获 TLS 明文；可选 PEM/PFX/P12 客户端证书只用于代理到目标站点的上游 mTLS 握手，密码不会出现在 API 视图或恢复文件中。

V3.3在V3.2恢复与分页架构之上增加前端增量更新内核。人工拦截与资产变化均使用最长25秒的事件驱动长轮询：后端变化时关闭通知通道并立即唤醒浏览器，空闲期不产生固定频率请求。任务变化拆为`asset_revision`、`progress_revision`、`finding_revision`和`interception_revision`，前端只拉取当前页面需要的数据集合；接口详情中的Raw请求、响应、高亮DOM及证据按内容令牌缓存，进度刷新不会重复解析长JSP或大JSON。

所有HTTP报文编辑和主要只读查看器使用同一套 CodeMirror 文档、折行、选区与语法 Decoration 管线。超长 URL、Cookie、JWT 或单行 JSON 不再依赖叠层同步滚动；超过 500 KiB 的文档会自动关闭 token Decoration，仍保持虚拟化编辑与正确光标定位。

创建任务时，目标URL的Host始终自动加入精确作用域；高级设置只填写额外Host。静态资源过滤采用内置后缀与`static_extensions`追加值的并集，管理员配置不会意外覆盖默认过滤规则。

## 1. 目标与边界

V3.0 把 V2.4 的“一条 Burp Raw HTTP 报文”入口扩展为“用户浏览站点时持续发现接口”，但不重写漏洞插件。首期采用手工浏览器代理：Edge、Firefox 或其他支持 HTTP 代理的浏览器连接 HappyScan 服务器上的任务端口，用户登录并点击业务菜单，系统自动形成接口资产清单，再调用原单报文扫描内核。

HTTPS 解密默认关闭。启用后管理员先下载并在浏览器中信任 HappyScan 本地 CA，作用域内 CONNECT 会由代理签发目标 Host 证书、解密为 HTTP/1.1，再进入与 HTTP 相同的捕获、拦截和扫描链路。范围外 CONNECT 继续保持原始隧道，不进入资产或扫描数据；未启用解密的范围内 CONNECT 也只计为隧道，不生成虚假的明文资产。

## 2. 分层

```text
Edge / Firefox / 其他浏览器
          │ HTTP 代理
          ▼
任务代理监听器 ─ 精确目标范围 / 资源硬上限
          │
          ├─ CONNECT 隧道（V3.0 不解密）
          │
          └─ HTTP 转发 ─ 请求/响应有界旁路捕获
                           │
                           ▼
                   过滤与接口指纹去重
                           │
                  ┌────────┴────────┐
                  ▼                 ▼
             接口资产仓库       有界扫描队列
              （进程内）             │
                                     ▼
                           V2.4 单报文扫描内核
                                     │
                                     ▼
                           接口 Finding / 站点汇总
```

管理 API 与页面只读取任务、资产和扫描快照；网络转发不能依赖页面轮询。代理连接取消、任务删除和进程退出必须传播到转发、排队扫描和后台协程。

V3.1支持两种作用域：指定目标URL的精确Host作用域，以及`target_url`留空或填写`*`的全局被动作用域。全局作用域只能运行Passive预设，禁止主动插件，并且代理必须监听本机环回地址，避免形成内网开放代理；浏览器已经产生的普通HTTP请求和响应会被转发、捕获、去重并直接作为被动分析基线，不产生额外目标请求。HTTPS仍仅记录CONNECT隧道计数，不能把不可见的TLS内容表述为已扫描。

V3.2进一步拆分转发范围与测试范围：环回监听上的目标外流量进入零捕获流式旁路，保证浏览器其他网站可访问；非环回监听仍返回范围错误，避免远程开放代理。只有测试范围内的请求才进入Body有界复制、人工拦截、资产去重和扫描。

### V3.1 人工拦截状态机

普通 HTTP 事务依次经过 `请求等待 → 请求放行/修改/丢弃 → 上游请求 → 响应等待 → 响应放行/修改/丢弃`。请求和响应使用独立开关，但共享同一有界队列。每条等待项只能完成一次，处理状态包括等待、原样放行、修改后放行、丢弃、超时和客户端取消。

- 默认超时 60 秒，范围 5–300 秒，默认超时动作是丢弃；管理前端固定使用该安全默认值，不提供运行时输入框；
- 每任务默认最多 50 条、最高 200 条同时等待，超过上限的流量受控旁路；
- 只保留最近 250 条内存历史；单条编辑缓冲最多 10MB；
- 关闭方向开关或停止代理会释放对应等待连接，不把后台扫描和接口历史删除；
- 修改请求重新执行语法、Scheme、Host 和 Scope 校验；修改响应重新校验状态码和 Header；
- 压缩/二进制内容仍可原样放行或丢弃，但不允许经浏览器文本框修改；SSE、WebSocket 和超限报文直接旁路。

## 3. 代理转发

浏览器发给显式代理的是 absolute-form 请求。代理层需要校验 Scheme、Host、端口和任务 Scope，移除逐跳 Header，再使用独立 Transport 转发；不能继承进程的 `HTTP_PROXY`、`HTTPS_PROXY` 环境变量。请求 Body 只能读取一次，转发与捕获必须共享一个有界副本，不能因为扫描而截断浏览器实际上传的文件。

响应应优先流式返回浏览器，同时旁路保存最多配置上限的副本。超出上限时记录原始长度和截断状态，不能把截断响应描述为完整基线。`Set-Cookie` 等重复 Header、压缩编码、Chunked、204/304、重定向、长 JSP 和 Multipart 二进制均应保持语义。

CONNECT 只允许任务 Scope 内的 Host。默认采用双向透明复制、五分钟连接期限和每任务 256 条连接上限，任务停止时主动关闭。启用 `intercept_tls` 且浏览器信任 HappyScan CA 时，范围内 CONNECT 改由本地 CA 为目标 Host 签发短期证书，解密出的 HTTP/1.1 重新进入普通代理链路；范围外或未启用解密的 CONNECT 不保存 TLS 明文。配置 `client_tls_file` 时，代理使用该 PEM/PFX/P12 证书与目标建立上游 mTLS，证书密码只用于任务创建时解析，不写入恢复状态。

## 4. 资产指纹与去重

推荐指纹：

```text
method + scheme + canonical_host + normalized_path
       + content_type_family + parameter_shape
```

路径中的整数、UUID 和明确的长随机标识可归一化；Query、Form、JSON、XML 与 Multipart 使用字段名、嵌套路径和标量类型形成结构摘要。GraphQL 需要加入 operationName/操作类型，文件上传需要加入文件字段结构。不同 HTTP 方法、不同 Content-Type 或明显不同业务操作不得合并。

同一指纹重复出现时更新 `seen_count`、首次/最后时间和代表性报文。新的已认证样本可以替换较弱样本，但不能让静态资源、登录失败页或大文件无界占用内存。

## 5. 扫描调度

捕获成功响应可以作为 V2 引擎的首条基线，因此对 POST/上传等非幂等接口不再额外发送一次预检。自动扫描只将首次可扫描资产入队；重复捕获、已排队和运行中的资产不能重复投递。手工重扫显式创建新一轮扫描，并沿用 V2 的任务、进程、目标三级限流和请求预算。

状态至少区分：

```text
observed → queued → running → completed
                   └────────→ failed
```

过滤、HTTPS 隧道、不适用、队列满和任务停止需要独立原因，不能统一显示成“无漏洞”。

## 6. 热内存与本地恢复

前端轮询只读取内存摘要，磁盘不位于请求热路径。每个任务在`var/webscan_state/<task_id>/`保存权限受限的`session.json`和按接口拆分的`assets/<asset_id>.json.gz`；写入通过400毫秒合并队列、临时文件、同步落盘和替换完成。接口快照包含一份代表性请求/响应、基线、进度与Finding，重复接口覆盖自身文件，不复制多份报文。

正常退出会刷新所有脏数据；异常退出后，下一次启动读取任务元数据和接口快照。恢复任务固定为已停止，旧浏览器Owner清空，排队或运行状态改为失败并注明进程中断，禁止自动重放非幂等请求或主动Payload。明确删除任务时移除对应恢复目录；关闭代理只保存状态，不删除记录。

列表API按页返回不含Raw报文与Finding的摘要。历史资产由服务端维护按`LastSeen`排列的增量链表索引：无筛选第一页只遍历最新10个节点，接近O(10)，不会为每次刷新重新收集和排序全部资产；搜索与状态筛选才执行O(N)扫描。漏洞汇总默认只返回漏洞类型、数量和接口数，点击某一类型后才返回对应接口摘要。只有选择具体接口时才读取完整详情，因此前端不会在刷新中重复传输和高亮全部HTTP证据。

代理设置页只读取任务摘要，接口资产页才读取分页资产和漏洞分组；插件清单、持久配置和`plugins.md`分别在进入扫描引擎、持久配置和使用说明时加载。超过500KB的Raw报文保留完整文本，但自动降级为单层纯文本渲染，避免为每行、Header和JSON Token创建大量DOM节点。

清空历史资产是独立于任务删除和停止代理的管理操作：前端执行两次确认，服务端还要求固定确认标识；执行后清空所有任务的接口索引、Finding和磁盘资产文件，但保留正在监听的代理与任务配置。

## 7. 数据与安全边界

V3.2不依赖外部数据库。WEB扫描热状态保存在进程内，恢复副本保存在本地文件，并受以下边界约束：

- 最大活动扫描任务、每个 WEB 任务最多 2000 个接口资产；
- 单请求/响应捕获字节数和全局总字节数；
- 扫描队列容量、每目标并发与 RPS；
- V2 子扫描任务沿用原有 TTL；WEB 任务在管理员删除或进程退出时释放；
- 删除任务时取消扫描、关闭代理端口并释放 Body。

由于浏览器流量包含完整 Cookie、Token 和业务数据，管理 API、页面和代理端口只能暴露在授权测试网络。即使扫描 API 按历史要求不启用 API Key，代理也必须执行任务目标 Scope；服务器安全组应进一步限制代理端口来源，避免形成开放代理。

## 8. 兼容性

- V1/V2 单报文 API 的路径、请求字段和响应机器码保持不变；
- 新能力使用 `/api/v3/web-scans` 命名空间；
- 根页面默认进入【WEB扫描】，原扫描中心通过 `/?single=true` 进入；
- 现有 `proxy_url` 仍表示扫描器访问目标时使用的上游代理，不能复用为浏览器入站代理监听；
- V2.4 配置升级时为 V3 字段补默认值并保留全部自定义规则；
- `rule_pack_version` 可以继续表示插件规则版本，程序版本单独为 V3.0。

## 9. 端口

默认管理端口为 8888，页面默认代理监听为 127.0.0.1:8088，OAST HTTP 为 61166，LDAP/JNDI 为 61167。远程浏览器接入时代理监听需改为服务器可达地址，并在安全组和防火墙中按来源放通。动态任务端口必须检测冲突；管理、回连与其他活动任务端口不能复用。
