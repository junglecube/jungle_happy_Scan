# V3.13.0 配置与升级说明

V3.13 增加了扫描前参数解析与按参数筛选，并改善漏洞证据中 URL 编码内容的可读性。

## 参数解析与筛选

扫描引擎请求报文下方的“参数解析”按钮只调用现有 `POST /api/v1/parse`，不会访问目标。服务器按已选插件计算 `plugin_parameters`：例如 SQL 只列出 SQL 插件会变异的点，文件上传列出文件字段，短信、SSRF、文件读取列出语义候选；被动、固定路径或纯响应分析插件没有可变异参数时返回空列表。

文本框默认直接显示 `number`、`query:number`、`json:user.id`，不额外包裹 `[query]` 方括号；手工输入时兼容 `[number]`、`[query:number]` 等形式。保存扫描时，非空内容作为可选的 `parameter_scope` 字段同时发送到原有 `/api/v1/plan` 和 `/api/v1/scan`；空文本框保持旧版全量行为。选择器为不区分大小写的精确匹配，持久配置中的 `excluded_parameter_names` 在解析和扫描前都会过滤。配置排除项填写 `Cookie` 时，会排除整个 Cookie 集合及从 Cookie 直接派生的特殊候选。文件字段和会话凭据等由插件从原请求派生的候选也应用同一筛选。

这是现有请求体的向后兼容扩展，没有新增路由；未识别 `parameter_scope` 的旧客户端仍按全量扫描处理。参数解析本身不发送漏洞请求，因此可以安全地反复点击或编辑结果。

## URL 编码证据

漏洞结果中的请求证据增加“可读预览”：只对请求目标中的 Query 组件和 `application/x-www-form-urlencoded` 表单值做组件级 URL 解码，并将结果作为纯文本显示。实际发送的 URL 编码报文保留在“查看实际发送的 URL 编码报文”折叠项中，便于复现；返回报文继续显示原始字节语义，不会被全局解码或当作 HTML 执行。

## 升级

1. 停止正在运行的旧进程。
2. 用 Linux amd64 的 V3.13.0 可执行文件替换原二进制并保留执行权限。
3. 保留原 `config/`、客户端证书、签名脚本和 `var/` 后启动。

本版本没有新增持久配置字段，原 V3.12 及更早的 config 可以直接沿用，无需迁移或替换配置文件。启动后可在版本页面看到 V3.13.0，并通过 `-version` 和 `/api/health` 验证。
