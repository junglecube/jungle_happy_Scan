# V3.9.0：扫描判定修复与业务结果规则

## 更新范围

修复白盒审计项 1–9；文件读取目标仍为 Linux。未扩展审计项 10 中的 CORS、CSRF、IDOR、SSTI 探针。业务规则是共享判定能力，不新增独立扫描插件。

- 短信：成功／失败／未知三态；显式失败优先，未知不再按 HTTP 200 计成功。次数、阈值和窗口可配置；喷洒仅使用持久规则中的号码池，不自动补足；记录发送时间偏移，并将限速导致的窗口／并发覆盖不足单独展示。
- XXE：移除重复 XML 声明，按目标 CDATA 容器替换；内部实体使用字符引用编码随机标记，避免原文反射误报；发送前检查文档基本结构。
- 上传：修复最终无条件低危覆盖。业务接受、可访问文件、服务端执行分别定级。成功语义允许与正常上传基线相同；单纯回显提交文件名或返回 path 不作为接受证据。普通文件回读比对原始字节并记录 SHA-256。
- XSS：逐反射上下文检查，编码副本不否定其他位置；二次响应再次检查 MIME；支持注释、textarea/title/style 等闭合，修复 HTML 属性反斜杠判断，区分脚本注释与数据脚本。仍仅报告候选，不虚构浏览器执行。
- SQL：快速保留其他引号恢复方式以及数值／字符串兜底；深度先轮询参数完成低成本布尔检查，再执行时间及其他阶段；保持完整复核组预算。双剂量支持有界的重复行执行倍率；不支持的时间函数显示覆盖不足。没有新增 SQL Server/Oracle 时间适配器。
- 评分：分数不再将 Firm 自动升级成“确认漏洞”。
- 回连：SSRF／XXE 在发送失败、超时或预算退出时仍结算已发送探针；支持配置同步等待和迟到补报窗口。SSRF 外部请求证据默认中危，不等同于私网访问或严重影响。
- 文件读取：参数名之外识别路径值；Linux 指纹支持 JSON 字符串及 Base64 包装；添加随机不存在文件对照，再重复确认。
- 敏感信息：validator 与显示名称分离，输出命中数及最多五个样本；启用敏感插件时增量分析主动响应，排除直接反射的探针内容。格式命中不代表越权。

## 持久配置界面

公共配置在前、插件配置在后。桌面端公共配置卡片和插件卡片均按单列排列，插件规则采用与扫描引擎一致的中文小卡片并按类别配色；点击卡片在原位置展开配置，再次点击同一卡片收起，切换时保留草稿，最后统一保存。短信次数／窗口移到短信配置，SQL 报错设置移到 SQL 配置，回连窗口集中在公共离线回连配置。此调整仅涉及前端，配置 API 和扫描逻辑不变。

## 前台业务规则

在【持久配置 → 响应语义】分别填写业务成功关键词和业务失败关键词，每行一个词或短语，按响应是否包含关键词判定。成功与失败同时命中时失败优先，未命中保持未知。使用既有配置保存密码保存，新任务立即使用新规则，无需重启。前台不要求编辑 JSON；保存时自动转换为后端现有业务规则字段。

```json
[
  {
    "name": "短信发送被拒绝",
    "plugin_ids": ["sms_abuse"],
    "url_pattern": "^/api/otp/",
    "json_path": "$.data.accepted",
    "equals": "false",
    "outcome": "failure"
  },
  {
    "name": "上传业务成功",
    "plugin_ids": ["file_upload", "file_upload_execution"],
    "status_codes": [200, 201],
    "json_path": "$.result.code",
    "equals": "OK",
    "outcome": "success"
  }
]
```

一条规则中的条件全部满足才命中；多条命中时 failure 优先。`plugin_ids` 不填则适用于所有插件，`url_pattern` 匹配请求 Target（路径及查询串）。`json_path` 支持根 `$`、点分字段和数组下标，例如 `$.items[0].status`，不支持通配符、过滤器或递归路径。`equals` 为字符串，与 JSON 标量的文本表示比较；`pattern` 为 RE2 正则，填写 json_path 时匹配该字段，否则匹配整个 Body。`status_codes` 只筛选规则，不将任意 2xx 自动视为业务成功。

短信和上传总是使用严格业务判定；配置匹配的共享规则也会传递到使用通用成功判定的其他插件。SQL 可使用相同规则参与业务差分。既有 `success_patterns` 和插件自定义成功正则保留为兼容入口；标准 JSON 状态包优先解析，内置泛化 code 正则不把数据记录误认成响应状态。

新增配置：

```json
{
  "config_version": 33,
  "business_rules": [],
  "sms": {"attempts": 30, "threshold": 5, "window_seconds": 60},
  "callback_wait_seconds": 8,
  "callback_late_seconds": 120
}
```

喷洒号码仍在 `plugin_rules.sms_abuse.payloads` 中配置 `kind: "spray_number"`。空号码池关闭喷洒，保留同号码测试；号码池不自动扩展。敏感信息规则可设置 `validator: "cn_id" | "luhn" | "ip" | "none"`，省略时兼容历史规则名称。

迟到回连仅在当前进程、任务保留时间及配置窗口内关联，不跨进程重启持久化；取消或删除任务会停止观察。前台在有待观察回连时继续更新结果。

## 仅替换二进制升级

1. 停止旧进程，保留原启动参数、工作目录、config 文件和签名脚本目录。
2. 用对应 CPU 架构的 V3.9.0 可执行文件替换原文件，恢复执行权限。
3. 使用原启动命令重启。无需复制发行包中的配置，也无需人工编辑原 config。

首次打开旧配置时，程序自动升级到 config_version 33；先保存原始字节备份 `config.json.pre-v33.bak`，再原子写回迁移配置。v31/v32 配置保留现有监听、代理、会话、规则与自定义值；v31 还补齐此前 SQL 时间版本的缺失默认规则，不覆盖自定义同名规则。更早配置延续已有历史迁移机制。配置目录需沿用原有可写权限。第二次启动不重复迁移；新字段随后可在前台调整。

二进制内嵌前台资源，因此只替换可执行文件即可更新界面。JS 签名所需的外部 Node 和已有签名脚本继续沿用。
