身份、CSRF 与扫描排除

命中的参数无论位于 Query、Form、JSON（含数组和嵌套对象）、Multipart、Cookie 或主动扫描 Header，都不会成为 Payload 变异点；其内部嵌套 JSON/XML/Base64 内容也不会继续展开。

离线回连

HTTP 回连默认监听 61166，LDAP/JNDI 安全接收器默认监听 61167；基础地址应填写目标服务器能够访问的扫描器 IP 或域名。两类监听器只接收一次性 Token，LDAP 端不返回远程类或对象。

V3.6.4

2026-09-04

为同步扫描增加原始请求鉴权预检与响应一致性校验，避免失效会话被误当成有效基线，并保留完整的失败诊断。

原始报文→鉴权预检→响应相似度→首个扫描基线→正式扫描

同步鉴权预检

  • jungle_happy_scan 与 Lite 接口现在先发送未修改的原始报文；响应为 401/403 或命中 denied_patterns 时直接返回失败。
  • 预检失败不会创建扫描任务，也不会继续发送插件探测请求；V1、V2、Full、Lite 和根路径兼容别名共用同一门禁。

捕获响应一致性

  • 同步接口可接收调用方捕获的原始 response，实时预检响应与其相似度低于 0.90 时停止扫描。
  • 成功预检的实时响应直接作为首个扫描基线，避免状态变更接口重复发送原始请求。

机器可读诊断

  • connectivity 增加网络状态、鉴权状态、失败原因、命中规则和响应相似度字段，不返回完整响应正文。
  • 相似度指标同步写入 Finding evidence；普通异步扫描、手动连通性和 WEB 代理扫描保持原有入口行为。

V3.1

2026-07-29

在 V3.0 浏览器代理之上增加完整的普通 HTTP 双向人工拦截：请求和响应均可查看、编辑并通过 Forward 放行或通过 Drop 丢弃。

浏览器→请求拦截→目标系统→响应拦截→浏览器

双向拦截工作台

  • 请求和响应拥有独立开关，待处理队列实时展示方向、URL、状态、截止时间和编辑能力。
  • Raw 报文使用 Burp 风格的 Forward 和 Drop；Forward 提交编辑器当前内容，修改请求会重新解析并校验作用域，修改响应会校验状态行和 Header。

资源与失败边界

  • 默认等待 60 秒并自动丢弃，单任务最多 50 条待处理、保留 250 条内存历史、单条可编辑报文上限 10MB。
  • 关闭拦截开关或代理会释放等待项；超限报文、流式响应、WebSocket 和不可安全编辑的二进制采用受控旁路。

HTTPS / mTLS 边界

  • HTTPS 与 mTLS 继续由浏览器完成 TLS 握手，HappyScan 仅 CONNECT 透传，因此无需把客户端私钥交给代理。
  • 未启用受信任 CA 的情况下不伪造“已拦截 HTTPS”；TLS 明文修改不属于本版本能力。

  • 重复流量更新捕获次数、最后发现时间和代表样本，不会为正在排队、扫描或已完成的同一接口重复创建任务。

扫描调度与结果汇总

  • 代理层只负责捕获、作用域、过滤和去重，代表报文继续投递给 V2.4 引擎，复用全部插件、持久配置、预算、限流、覆盖率与证据规则。
  • 支持新接口自动扫描和单接口手动重扫；页面展示代理状态、捕获请求、去重接口、逐接口请求进度、最高风险和站点漏洞报告。
  • V3 REST API 为纯增量接口，现有 V1/V2 单报文接口、同步接口及“单报文扫描”页面保持兼容。

资源与安全边界

  • 会话、代表样本、扫描关联和结果使用有界内存，不引入数据库，进程重启或管理员删除任务后记录消失。
  • 严格执行精确 Host 作用域、静态资源过滤、5 MiB 捕获上限、接口数量上限和仅淘汰非扫描资产的 LRU 策略。
  • 自动扫描复用现有全局队列、并发、目标限流和请求预算；移除逐跳代理头，证书密码与代理凭据不会写入接口资产。

V2.4

2026-07-28

本版本只专注 SQL 注入：重构单引号筛选、上下文选择、A-B-B-A Oracle、响应差分、预算与覆盖率，使 Spring/Spring Boot、MyBatis、存储过程、CTP、JSP 以及 MySQL、PostgreSQL/GaussDB 场景获得更稳定且可解释的结论。

SQL 准确率内核

  • 单引号 Gate 只裁剪错误恢复分支，不再错误跳过数值、布尔和其他上下文；Gate 响应不复用为确认样本，所有结论均由完整原子 A-B-B-A 请求组产生。
  • 普通单引号破坏/恢复只先报告疑似；两条独立恢复路径、条件错误、布尔或时间 Oracle 成立后再升级，降低字符校验、统一异常页和瞬时抖动误报。
  • 递归识别 JSON 对象、数组中的 code/returnCode/errorCode/status/success，并要求同一 JSON 路径形成稳定业务差分；JSP 可复用持久配置的成功/失败正则。

上下文与数据库适配

扫描规划与公平预算

  • 新增扫描前计划器，依据方法、Content-Type、参数语义和插件前置条件判断适用性，不适用插件明确跳过并说明原因。

  • 新增 POST /api/v1/plan，返回预计请求、预算、耗时、插入点和逐插件计划；扫描中心在创建任务前自动展示。

统一结论质量与二次验证

  • 所有发现统一计算 0–100 可信分，并归类为 confirmed、probable、exposure 或 informational；分数综合置信等级、重复证据和插件特性。
  • 按插件、输入点和标题去重；同一输入点出现注入、异常泄露、授权或服务端风险等多个独立信号时生成关联 ID 和聚合说明。
  • SQL 注入继续使用错误破坏/恢复反序确认、布尔真假反序确认和双轮延时对照；动态基线或鉴权失败响应不会直接报警。
  • 文件上传在上传成功后优先读取响应给出的同源地址，以唯一 canary 确认文件落地；Mass Assignment 在可定位资源时执行二次读取确认持久化。
  • GraphQL 批处理阈值提升为一次接受 20 个操作，别名阈值提升为 32 个，降低仅支持正常批量能力造成的误报。

复杂报文与协议适配

  • 插入点扩展到 URL 数字/UUID 路径段、业务 Cookie、可配置 Header、XML 属性、CDATA、GraphQL variables、multipart 文件名。
  • 识别 Query、Form、JSON、Cookie 和 Header 中的 Base64 JSON，并对其内部对象和数组字段执行解码、嵌套变异和原编码回填。
  • 新增 Normalized、强制 HTTP/1.1 和 Raw HTTP/1.1 三种传输模式；Raw 模式保留 Header 顺序、大小写和重复 Header，适配对报文格式敏感的旧网关。
  • 新增请求动态变换和基线响应提取：支持时间戳、UUID、正则替换、SHA-256、HMAC-SHA256、Base64，以及从 Body/Header 捕获 Token 后刷新后续请求。
  • 保留 Burp multipart 非二进制文件内容与 CRLF 边界，文件名本身也成为可扫描输入点。

共享服务安全与验证工程

  • 新增单来源每分钟任务限额、共享服务模式和配置读写 CIDR；共享模式强制要求目标白名单，防止服务被当作任意网络访问代理。
  • 配置保存密码支持通过 JUNGLE_CONFIG_PASSWORD 环境变量覆盖；配置读取自动遮蔽 HMAC Secret，保存时安全恢复未修改的密文值。
  • 扫描创建写入不含报文内容的审计日志；请求限额表自动清理过期来源，避免长期共享部署产生无界内存增长。
  • 新增计划器、覆盖率、结论去重关联、嵌套 Base64、动态签名/响应提取、Raw HTTP/1.1 的单元和集成测试，并加入 Raw HTTP 解析与插入点发现 Fuzz 入口。
  • 前端新增计划摘要、覆盖率表、关联风险卡片和可信分 Badge，所有新配置均可在持久配置页管理。
  • 配置保存密码改为保存栏内显式密码框，移除对浏览器原生 prompt 弹窗的依赖，保存成功后立即清空。

FOUNDATION

V1

2026-07-15

完成从 Python 方案到纯 Go 离线扫描器的架构重构，建立高并发任务引擎、插件系统、Raw HTTP 传输层和内存结果模型。

HTTP API→任务调度器→插件 Goroutine→并发 Transport→目标系统

Go 高并发任务引擎

  • 每个扫描请求创建独立 Task，使用随机扫描 ID、独立 context、进度、告警、结果和生命周期状态。
  • 全局任务槽限制同时运行的扫描数量；超出上限的任务进入 queued，槽位释放后由事件通道立即唤醒，避免忙轮询。
  • 同一任务中的漏洞插件使用 Goroutine 并发执行，通过 WaitGroup 汇合结果；慢插件不会阻塞其他插件推进。
  • 任务状态、漏洞数组、进度和订阅者使用 RWMutex 保护，读状态与写进度可安全并发，已通过 Go race detector 验证。
  • 取消操作通过 context 传播到排队、限速等待、HTTP 请求、回连等待和插件执行；客户端主动取消后能够快速释放连接与 Goroutine。
  • 任务完成后只在内存保留到配置的 TTL，定时删除，不使用数据库，也不持久保存历史漏洞。

三层并发与流量控制

  • 第一层由 max_active_scans 控制全局活跃任务数，防止大量扫描同时占满服务器。
  • 第二层为插件级 Goroutine 并行，不同漏洞类型共享同一次基线和任务 Transport。
  • 第三层由每任务 semaphore 控制实际在途 HTTP 请求数，严格限制目标连接压力。
  • 令牌节奏限速器按 requests_per_second 控制发包速率，同时设置单任务最大请求数、最大响应体和超时硬边界。
  • HTTP Transport 启用 Keep-Alive 和连接池复用，避免每个 Payload 重建 TCP/TLS 连接；任务结束统一关闭空闲连接。
  • DNS 结果在任务内缓存并固定到已校验 IP，减少重复解析并降低 DNS 重绑定风险。

Raw HTTP 与网络安全边界

  • 直接解析 Burp Suite 标准 Raw HTTP，保留 Method、Target、Header、Cookie、Body 与 multipart 结构。
  • 自动发现 Query、Form、JSON、Header 和 multipart 文件插入点，并在克隆请求上执行定点变异。
  • 支持 Cookie、Session、token、des_sessionid、sessionid 等可配置会话标识，适配不同 Spring Boot 接口。
  • 每次重定向重新校验目标 Host；空白名单自动收紧到原报文 Host，私网访问、TLS 校验和显式代理均由管理员控制。
  • 不读取环境中的 HTTP_PROXY/HTTPS_PROXY；只有管理员显式配置代理时才出站到该代理。

插件化扫描与准确率设计

  • 每种漏洞一个独立 Go 插件文件，通过统一 Meta、Scan、Progress 和 Evidence 接口注册。
  • 首版覆盖未授权、SQL 注入、XXE、文件读取、危险上传、敏感信息、CORS、反射型 XSS，并扩展到 20 个插件。
  • 扫描前采集多份原始响应基线，对动态字段归一化，再使用状态码、结构、文本相似度和业务成功/失败语义联合判定。
  • 主动检测优先使用无害 canary、成对 Payload 和对照响应，不以读取真实业务数据作为成功条件。
  • Evidence 保存请求、响应头、命中上下文原文和差分指标，便于管理人员人工复核而不是只输出漏洞名称。

API、进度与离线交付

  • 提供扫描创建、状态、结果、取消、删除、插件元数据、配置、解析和健康检查接口。
  • 进度同时支持轮询和 SSE，事件包含 snapshot、progress、finding、warning、done。
  • 前端页面通过 Go embed 编译进程序，不依赖 CDN、npm、遥测、许可证服务或在线更新。
  • 使用 CGO_ENABLED=0 交叉编译为静态可执行文件，部署服务器无需任何语言运行时。
  • 监听所有网卡，适合作为测试网络内部服务；不内置 API Key，访问控制由部署网络边界负责。
